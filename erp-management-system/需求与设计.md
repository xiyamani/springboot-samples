# ERP 管理系统需求与设计

## 课程目标

以制造企业采购、销售和仓储为场景，完成一套可运行的桌面业务系统，并展示角色分工、审批、数据库事务、接口契约、异常恢复、SQL 优化与操作追溯。

采用单应用架构：Vue 静态页面由 Spring Boot 提供，业务 API、接口适配器、本地平台测试端点和定时调度器处于同一个 Java 进程。用户只启动一次、打开一个地址。

## 架构

```text
桌面浏览器 Vue
    ↓ Session + CSRF / REST JSON
Spring Security → Spring MVC → 业务服务 → MyBatis → H2 文件库
                                  ↓ 同事务创建
                             integration_jobs
                                  ↓ 定时或人工发送
                             HTTP 接口适配器
                                  ↓ 本机 HTTP
                         /training-api 测试端点
                   ERP JSON / WMS JSON / MOM SOAP XML
```

本地测试端点代表外部系统边界，使用独立令牌、回执表和幂等请求号。适配器确实执行 HTTP 请求；外部平台业务由本地实现。`KingdeeApiClient` 另提供 MOCK/REAL 切换，MOCK 返回按金蝶常用字段组织的采购、销售和库存单据，REAL 保留登录与动态单据查询的 HTTP 边界。这不是金蝶官方接口兼容性证明。

## 业务模型

| 表 | 职责 |
| --- | --- |
| products / partners | 商品、往来单位 |
| business_orders / order_lines | 采购销售单头与明细 |
| inventory_movements | 库存变动、成本与结存 |
| order_workflows | 提交人、审批人、意见、审批状态 |
| integration_jobs / integration_attempts | 发送任务和逐次回执 |
| platform_receipts | 测试平台幂等回执 |
| integration_exchanges | 物料及生产协同报文 |
| manufacturing_orders / manufacturing_reports | 工单、完成量与重复报工保护 |
| audit_logs | 操作人、动作、对象、时间 |
| sql_lab_orders | 独立数据库优化样例表，业务页面不展示 |

业务状态为 DRAFT、COMPLETED、CANCELLED；审批状态独立保存为 DRAFT、SUBMITTED、APPROVED、REJECTED，避免破坏已有业务数据。已有完成单据保持历史结果，不伪造历史审批人。

## 事务与一致性

单据提交前必须为草稿。待审批单据不能直接作废；审批通过后才能过账。审批与过账先锁定单据，避免重复执行。

采购入库使用移动加权平均成本；销售按当前平均成本计算出库成本。数量最多三位小数，单价最多两位；单行金额四舍五入到分，再汇总。业务日期不得晚于上海时区当前日期，补录历史日期不会重算历史成本。

过账中的库存、流水、订单状态和两条接口任务在同一个数据库事务中提交。库存不足时整单回滚。已完成单据不能重复执行或直接作废。

接口发送在业务过账之后执行。网络失败不撤销已经完成的库存业务，而是记录失败任务供重试。任务使用稳定幂等键，平台保存唯一回执；成功任务不再次发送。当前任务队列处理待发送任务，失败任务由管理员人工重试，未实现生产级消息中间件或无限自动重试。

生产报工锁定工单，阻止超量；同一请求号和相同内容重复到达时返回既有结果，不重复累加。同一请求号若内容不一致则拒绝。

## 权限与审计

四个角色的写入权限在服务器检查，界面同时按角色显示操作。Session 登录、BCrypt 密码、CSRF 校验用于本地课程环境。平台端点使用测试令牌；应用默认仅监听本机。

审计记录包括资料维护、建单、提交、审核、过账、同步和报工；页面显示最近 300 条。未实现审计防篡改、企业身份源、密码管理或生产运维体系。

## 金蝶 Mock 方案

金蝶适配器以 `erp.kingdee.mode=MOCK` 启动，界面显示为“金蝶云星辰业务账套”，模拟登录 token、动态单据查询和保存回执。采购、销售、库存分别使用 `PUR_PurchaseOrder`、`SAL_SaleOrder`、`STK_InStock` 作为 formId；每行包含单号、日期、物料编码/名称、数量、单价和往来单位。系统在适配边界把字段转换为内部模型，再进入库存和报表服务。

切换真实环境只替换 `REAL` 配置和服务地址，业务服务不改。真实接入前还需要按企业账套确认接口版本、组织/仓库编码、权限、分页、字段精度、失败重试和回调约定，并在测试账套完成联调。课程环境不声称已经取得这些资料。

MySQL 提供可选配置和建表脚本，未做真实数据库验收；SQL Server、Oracle、金蝶 BOS 及官方 ERP 插件不列为已实现。课程技术清单中的备选工具不等于每项都必须使用，最终以老师评分标准为准。
