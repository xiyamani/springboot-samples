# 测试与验收

## 已执行的后端测试

执行 `mvn test`，共 20 项，失败 0，错误 0。

`BusinessFlowTest` 共 10 项，验证库存与成本业务，包括库存不足、多行事务回滚、重复过账防护、金额精度、CSV 与输入校验。测试关闭审批强制要求，专门隔离验证基础库存规则。

`WorkflowIntegrationTest` 共 9 项，在随机端口运行完整服务，验证：

1. 审批前禁止过账、驳回原因必填、驳回后重新提交、过账产生两条任务。
2. 审批角色不能建单，匿名不能读取业务。
3. 实际 HTTP 调用遇到 WMS 503 后保存失败，重试成功，重复任务返回既有回执。
4. 物料重复同步不重复新增。
5. SOAP 报工只累计一次，超量报工拒绝。
6. XML 外部实体文档拒绝解析。
7. 20,000 行数据库优化样例结果一致，MySQL 脚本包含 `idx_lab_partner_date` 索引方案。
8. 表单登录创建会话，退出使会话失效，错误密码拒绝。
9. 缺少 CSRF 的业务写入与缺少平台令牌的请求被拒绝。

测试使用隔离内存数据库，不修改当前账套。后端测试报告保存在构建后的 `target/surefire-reports`。

## 浏览器验收

浏览器验收脚本使用独立临时账套，通过真实桌面浏览器执行登录、导航、新增商品、角色分工采购、销售、同步、失败重试、报工、报文、导出和审计检查。9 组检查全部通过，未发现 JavaScript 运行错误。数据库优化脚本另行在本机 MySQL 中执行验证。

Postman 集合的 18 个请求已通过脚本按集合配置顺序重放，校验登录令牌、采购流程、接口回执和报工幂等；本次未使用 Postman 桌面客户端执行。

金蝶适配器 MOCK 模式额外验证了登录响应、采购/销售/库存三类 formId、标准字段解析和内部字段转换；REAL 模式仅做配置路径检查，未连接外部企业服务。

四个账号均通过浏览器验证了独立工作台、角色导航和越权页面回退：管理员 10 个业务模块，业务员 6 个，审批主管 7 个，仓库员 6 个。

桌面检查覆盖 1280、1440、1920 宽度；没有移动端验收要求。

最终账套执行停止、重新启动后再次读取验证：10 项商品的库存与平均成本、11 张单据的状态、2 张生产工单的完成量均与重启前一致。该账套含一次接口验收采购和一次报工；源码交付包不包含当前运行数据库，首次运行自动建立独立课程数据。

## 环境与限制

实际执行环境为 Windows、Java 21、H2、Chrome。本地服务 API 与同进程测试平台间仍通过真实 HTTP 通信。

MySQL、SQL Server、Oracle、Docker、Linux、官方金蝶环境、WMS/MOM 商业产品未在本次环境实测。不将参考配置或测试响应作为企业产品接入成功的证据。

固定教学账号、单机文件库和简单队列用于课程交付；尚未进行高并发、灾备、企业安全和财务合规验收。
